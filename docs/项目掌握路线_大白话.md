# MeetingMind 项目掌握路线（冻结版）

目标不是把 363 个文件全部读完，而是亲手复现一条完整主链，并能解释每个关键设计为什么存在。完成第六阶段后，就基本覆盖简历中的主要内容。

## 先读哪些文件

按下面顺序，不要一开始钻进前端或所有历史文档：

1. `README.md`
2. `docs/项目总览_大白话.md`
3. `docs/架构解析/输入预处理层.md`
4. `docs/架构解析/记忆层.md`

读完前十项，先用自己的话画出“请求从哪里进、经过哪些节点、结果从哪里出”。

## 第一阶段：跑通最小环境

目标：知道项目如何启动，不追求马上理解全部代码。

建议操作：

1. 激活 `meetingmind-gpu` conda 环境。
2. 启动宿主机 PostgreSQL，以及 Docker 中的 Redis、RabbitMQ、Milvus；随后在 Conda 环境中分别启动后端、Worker 和前端。长期记忆索引当前保持关闭。
3. 阅读 `docs/API与运行_大白话.md` 和 `.env.example`。
4. 启动后端，访问健康检查接口。
5. 不修改生产代码，只记录每个服务的作用。

掌握标准：能解释为什么 Redis、PostgreSQL、Milvus、RabbitMQ 各自存在。

## 第二阶段：复现输入到路由

重点文件：

亲手验证四类输入：普通问答、混合任务、包含否定约束的输入、疑似 Prompt 注入的输入。

## 到这里算“掌握核心板块”

满足以下条件即可认为已经掌握项目核心，不必继续深挖前端：

- 能画出六层主链及数据流；
- 能从 API 请求追到 LangGraph 节点；
- 能解释 InputEnvelope、TaskAnchor、记忆、检索、工具门禁和引用；
- 能亲手跑通正常路径、权限拒绝、工具确认、队列恢复；
- 能解释 100 条冻结评测的来源、限制和指标；
- 能指出当前系统没有证明的内容：全库检索泛化、生产级并发、完整人工问答质量。

## 面试复述模板

可以按这个顺序介绍：

1. 先说业务问题：会议资料难检索、答案难核验、行动项难沉淀；
2. 再说主链：输入预处理 → 路由/规划 → 混合检索 → 结构化输出 → 受控工具执行；
3. 再说安全：来源隔离、ACL、HITL、幂等、审计和队列恢复；
4. 再说证据：28 场会议、100 条冻结任务、120 项契约测试和固定业务演示；
5. 最后主动说边界：当前是可复现的应用工程项目，不包装成生产级泛化或完整 RAG 研究结论。

## 不建议的学习方式

- 不要从 HTML 样式、前端组件或历史日志开始；
- 不要死记所有类名和配置项；
- 不要重复消耗云 API 来“证明”已经冻结的结果；
- 不要把评测报告中的受控指标扩大解释为生产效果；
- 不要只看成功案例，至少要能讲一个引用覆盖不足、约束 F1 偏低或检索召回失败的 Bad Case。
