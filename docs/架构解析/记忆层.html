记忆层

这份文档用来说明：Agent 当前记住什么、保存在哪里、什么时候覆盖或删除，以及任务中断后如何继续。 2026-09-04 已完成当前代码范围内的记忆层优化；真实 PostgreSQL、RabbitMQ、Milvus、Neo4j、多副本和长会议效果仍需正式环境验收。

这一层负责什么

记忆层不是把所有聊天记录永久存起来，而是分开处理三件事：

  • 当前对话最近几轮说了什么。
  • Agent 运行到哪一步，能不能从中断处继续。
  • 哪些经过确认的事实值得跨请求保存。

当前项目采用：

  • MemoryManager：进程内有界短期记忆。
  • Checkpoint：保存可恢复的任务状态。
  • PostgreSQL：长期事实的权威主库。
  • Redis：HITL 确认状态和短期快照。
  • RabbitMQ：长期事实索引更新的可靠投递。
  • Milvus：长期事实的向量检索索引。
  • Neo4j：实体和关系的派生索引。

核心问题与改进安排

1. 写入信噪比：什么该记，什么该丢

当前方案：

  • MemoryWriteGate 只允许写入有边界的最终问答和结构化事实。
  • 空答案、控制字符、超长正文会被拒绝或截断。
  • conversation、fact、decision 分开保存，不把计划、反思和工具日志混成事实。
  • Checkpoint 使用字段白名单，不保存完整检索正文、CoT、回调和未知运行时对象。
  • 长期事实保留 key/value、来源、时间、置信度、重要性和内容哈希。

大白话总结：不是 Agent 说过的每句话都值得永久保存。大段日志、思维链和重复内容会被挡住，只有能帮助后续任务的最终结果或明确事实才有机会进入记忆。

改进方案：

  • 长期事实写入必须继续保留数字、ID、时间和否定条件，不能只保存模糊摘要。
  • 需要摘要时，只保存“摘要 + 原始记录 ID + 版本”，原始事实不能被摘要替代。
  • 对写入来源、写入人和写入原因增加审计记录。

2. 相似度和时间盲区：想起了相似内容，却想错了时间

当前方案：

  • 记忆按 user_id、thread_id 和 task_namespace 隔离。
  • 事实保存 valid_from、valid_until、created_at 和 supersedes_id。
  • 进程内检索会综合词面命中、可选 dense_score、时间衰减、置信度和重要性。
  • PostgreSQL 检索先做范围过滤，再做词面召回；Milvus 只能作为派生向量索引。
  • 已被覆盖或过期的事实默认不再召回。

大白话总结：记忆不能只看“像不像”，还要看是不是同一个任务、是不是最新说法、是不是已经过期。用户把北京改成上海时，旧地点不能继续干扰当前计划。

改进方案：

  • 生产检索采用 BM25、向量、时间和置信度的混合排序。
  • 固定 embedding 模型和版本，模型升级时重建派生向量。
  • 新旧向量不能直接混排，索引失效时从 PostgreSQL 重建。

3. 事实冲突：新说法到底是覆盖还是并存

当前方案：

  • 同一任务空间、同一 key 的新事实默认把旧事实标记为 superseded。
  • 旧事实不会被物理覆盖，仍保留原值、生效时间和覆盖关系。
  • PostgreSQL 支持 conflict_group_id 和 supersede_previous=false，无法判断时可以保留冲突组。
  • 事实带有置信度、来源和重要性，供后续重排和人工确认使用。

大白话总结：用户说“去北京”后又说“改去上海”，通常上海覆盖北京；但“我喜欢辣”和“医生要求我少吃辣”可能是两个场景，不能简单让后一句把前一句抹掉。

改进方案：

  • 增加场景、时间和人工确认状态，区分“改口”和“并存事实”。
  • 冲突未解决时，规划层不能自行平均结论，应暂停或请求用户确认。
  • 冲突组的召回结果要明确标注“当前有效”“历史版本”或“待确认”。

4. 压缩和摘要导致信息坍缩

当前方案：

  • Checkpoint 对字符串、列表、字典和工具上下文做有界压缩。
  • 超长值保留截断标记、预览和 SHA-256，避免误以为保存了完整正文。
  • 当前不自动生成长期摘要，不把摘要当作唯一事实来源。
  • 工具审计、Checkpoint 和长期事实分开保存，避免压缩时把错误原因混进去。

大白话总结：为了省空间可以截断，但不能把“错误码、重试次数、订单号、时间”悄悄压没，更不能让模型根据现在的猜测改写过去发生的事情。

改进方案：

  • 压缩前后对数字、ID、时间和否定条件做对照检查。
  • 摘要必须带原始记录引用和版本，发现关键字段缺失时不能用于决策。
  • 需要恢复的工具参数和幂等信息不能只保留自然语言摘要。

5. 跨任务和跨用户串台

当前方案：

  • SessionMemoryStore 按 thread_id 隔离用户和对话，并限制线程数量。
  • task_namespace 区分同一聊天中的不同任务。
  • API 支持显式 task_id；没有显式 ID 时才回退到短问题追问启发式。
  • PostgreSQL 长期记忆检索支持用户、线程、任务空间、会议和文档范围硬过滤。
  • delete_scope() 只允许带用户 ID 的范围删除，不能无条件清空全库。

大白话总结：用户从“订机票”切换到“写代码”时，靠窗座位不能跑到代码问题里；A 用户的会议事实也不能被 B 用户检索出来。

改进方案：

  • 新业务优先传递稳定的 task_id，逐步减少启发式任务判断。
  • 生产环境增加数据库租户隔离或行级安全策略。
  • 对任务切换、并行任务和跨会议检索增加串台率测试。

6. 反思和计划自指：记忆自己把自己绕进去

当前方案：

  • CoT、计划、反思和工具原始返回不会自动写入长期事实表。
  • Checkpoint 只保存恢复任务必需的状态，工具审计单独保存执行证据。
  • 长期事实和派生摘要分开，避免“反思的反思”被当成事实再次召回。
  • 默认不会把普通 Agent 回答自动升级为长期事实，必须显式调用 remember_fact()。

大白话总结：Agent 对某件事的想法不是事实本身。现在把用户事实、工具证据、计划和反思分开，避免下一轮把上一次的猜测当成新的真相。

改进方案：

  • 如需保存反思，只允许低权限、可删除的派生记录。
  • 禁止派生记录继续生成同类型派生记录，避免无限递归。
  • 反思结果必须引用原始事实，不能单独作为高风险工具调用依据。

7. 任务中断和恢复：记忆状态不能导致重复副作用

当前方案：

  • user_id、session_id、conversation_id、thread_id、run_id 和可选 task_id 分工明确。
  • Checkpoint 使用白名单、大小限制、加密、版本和保留期。
  • HITL 确认绑定 thread_id、agent_run_id、恢复快照和工具幂等键。
  • 恢复时重新核对当前用户权限、input.v1、TaskAnchor、任务空间和 Token 账本。
  • outbox 事件使用 claim 租约，发布进程崩溃后可以重新领取。

大白话总结：任务停在人工确认或服务重启时，系统要知道从哪一步继续，而且不能因为重试又重复发邮件、改数据或创建工单。

改进方案：

  • 生产环境使用 PostgreSQL Checkpoint saver，不把本地文件当作多副本方案。
  • 做真实“审批暂停 → 进程重启 → 恢复 → 只执行一次”的演练。
  • 对不完整、过期或归属不一致的恢复状态直接拒绝，不猜测修复。

长期记忆的实际分工

当前方案：

  • PostgreSQL 的 memory_records 是唯一事实来源。
  • memory_index_events 与事实写入在同一事务中提交。
  • outbox 发布器通过 RabbitMQ publisher confirm 投递更新事件，并处理重试、死信和租约。
  • MemoryIndexProjector 为 Milvus 和 Neo4j 提供注入式投影边界，没有真实投影器时拒绝确认消息。
  • AgentService 提供显式 remember_fact()、search_long_term_memory() 和 forget_long_term_memory()。

大白话总结：PG 负责记真相，Milvus 负责找相似内容，Neo4j 负责找关系，Redis 负责短期状态，RabbitMQ 负责可靠传消息。索引坏了可以重建，索引不能反过来修改事实。

改进方案：

  • 真实环境打开 MEMORY_INDEX_WORKER_ENABLED，注入 Milvus/Neo4j 投影器。
  • 增加 outbox 重复投递、部分失败、索引重建和最终一致性测试。
  • 生产检索先做权限硬过滤，再合并 BM25、向量、时间和置信度排序。

与输入层的接口

当前方案：

  • 输入层生成并校验 InputEnvelope、TaskAnchor、可选 task_id、来源权限、会议/文档范围和预算。
  • 记忆层沿用输入层的用户、线程、任务空间和资源范围，不重新解释目标，也不重新授予权限。
  • TaskAnchor 保存本轮“要完成什么”；长期事实只保存经过门禁的 key/value 和来源信息。
  • 输入层的 authority_rank、trust_level 和隔离标记不会在记忆层被升级成用户事实。

大白话总结：输入层先把“谁在问、要做什么、能看什么”说清楚，记忆层再按这条边界保存和查找。两层共用任务身份和权限范围，避免越权和串台。

改进方案：

  • 生产长期记忆写入必须携带 user_id、thread_id、task_namespace、meeting_id、document_id 和来源校验和。
  • TaskAnchor 或权限范围变化时，旧任务记忆先停止召回，必要时请求确认。
  • 用户改口由输入层意图/约束变化触发覆盖或冲突处理，不能只凭向量相似度决定新旧。

本层完整工作流

用户请求 + 当前身份 → 输入层生成并校验 input.v1/TaskAnchor/scope → 使用显式 task_id 或原问题和资源范围生成 task_namespace → 从有界短期记忆取得最近几轮 → Agent 图按 thread_id 和 run_id 执行 → 白名单状态写入 Checkpoint → 明确值得保存的事实通过 MemoryWriteGate 和 MemoryRepository 写入 PostgreSQL → 同事务写入 outbox → Worker 通过 RabbitMQ 更新 Milvus/Neo4j → 需要确认时保存 HITL 快照 → 恢复前重新核对身份、权限、输入契约、任务空间和预算 → 只从待执行位置继续。

当前代码对应关系

  • 记忆门禁、短期记忆、任务空间和事实覆盖：memory.py
  • Agent 状态和任务空间接线：state.py、agent_service.py
  • 输入契约：agent_input.py
  • 长期事实表和 outbox：memory.py
  • 长期事实写入、检索、删除和 outbox 发布：memory_repository.py
  • 索引 Worker：memory_index_worker.py
  • 长期记忆表迁移：0010_add_memory_records.py、0011_add_memory_conflict_group.py、0012_add_memory_event_lease.py

当前版本的边界

当前记忆层只承诺：

  1. 短期记忆、Checkpoint 和长期事实分开管理。
  2. 记忆写入、检索、覆盖、删除和任务隔离有明确代码边界。
  3. PostgreSQL 是长期事实主库，索引可以重建。
  4. 不可信资料、CoT、计划和反思不会自动升级为长期事实。
  5. 恢复前会重新核对身份、权限、输入契约和预算。

当前不承诺：

  1. 已经完成真实 PostgreSQL、RabbitMQ、Milvus、Neo4j 环境验收。
  2. 已经证明长会议下的检索准确率、Token 节省量和响应延迟。
  3. 自动识别所有“用户改口”和复杂场景冲突。
  4. 自动生成高质量长期摘要或跨用户画像。

当前已实现

  1. thread_id、run_id、task_id 和 task_namespace 的边界定义。
  2. 有界短期记忆、线程 LRU 和任务空间隔离。
  3. Checkpoint 白名单、压缩、加密、版本、保留期和恢复校验。
  4. HITL 恢复快照、租约和工具幂等边界。
  5. MemoryWriteGate 写入门禁和事实/会话/决定分类。
  6. 事实覆盖、冲突组、时间有效期、置信度和重要性字段。
  7. 混合记忆排序和主动遗忘。
  8. PostgreSQL 长期事实表和 outbox 事务边界。
  9. outbox claim、publisher confirm、失败重试、死信和崩溃后租约回收。
  10. 按用户、线程、任务、会议和文档范围软删除，并发送索引删除事件。
  11. 显式 remember_fact()、search_long_term_memory() 和 forget_long_term_memory() 接口。
  12. Milvus/Neo4j 注入式索引投影边界和 Worker 开关。
  13. 输入层 InputEnvelope/TaskAnchor/scope/task_id 与记忆层的任务空间关联。

本层明确不做

  1. 不把会议知识库、RAG 证据和长期事实合并成一张万能表。
  2. 不把普通模型回答、CoT、计划、反思或工具原始日志自动写入长期事实。
  3. 不在记忆层重新判定用户权限，也不允许无用户 ID 的全库删除。
  4. 不把 Milvus 或 Neo4j 当成事实主库。
  5. 不把开发用进程内记忆或本地文件 saver 宣称成多副本生产级方案。
  6. 不在本轮引入无限摘要、自动反思递归、跨用户画像或 Memory Evolver。

本层亮点总结

  1. 记忆分层清楚：短期对话、任务恢复和长期事实不再混在一起。
  2. 事实有版本：新说法可以覆盖旧说法，但旧记录仍可追溯。
  3. 任务不容易串台：task_id、task_namespace、用户和资源范围共同限制召回范围。
  4. PG 保证真相：Milvus、Neo4j 和 Redis 都是可重建或有边界的派生/短期存储。
  5. 写入有门禁：模型的计划、反思和工具日志不会悄悄变成长期事实。
  6. 删除可追踪：删除先软删除主库，再通过 outbox 通知索引。
  7. 恢复可控：Checkpoint、HITL、预算和幂等信息共同防止重复副作用。
  8. 层间关系明确：输入层负责目标和权限，记忆层负责按边界保存与召回。

本层验收依赖

  1. 记忆、Checkpoint、输入契约、Worker 和路由回归测试必须继续通过。
  2. 真实 PostgreSQL 迁移、写入、重启、并发、删除和备份恢复需要单独验证。
  3. 真实 RabbitMQ 环境需要验证 publisher confirm、重复投递、重试、死信和租约回收。
  4. 真实 Milvus/Neo4j 需要验证部分失败、索引重建和最终一致性。
  5. 真实长会议需要测量记忆召回准确率、旧事实干扰率、Token 消耗和响应时间。
  6. 用户改口、冲突组、跨任务切换和多用户并发需要形成固定验收集。

本轮确认

  1. 记忆层的本地代码闭环已完成，可以进入正式真实测试。
  2. 普通回答不会自动写入长期事实，长期写入必须显式、可审计。
  3. 输入层和记忆层共用 TaskAnchor、task_id、task_namespace 和资源范围。
  4. PostgreSQL 是长期事实唯一来源，Milvus/Neo4j 不能反向修改事实。
  5. 真实外部服务和长会议效果尚未被本地测试证明。
