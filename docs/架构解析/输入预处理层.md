输入预处理层

定位：把进入 Agent 的用户目标、身份作用域和外部材料整理成安全、稳定、可追踪的内部输入契约，再交给路由、规划和后续执行链路

架构：异构输入制品化 + 身份与资源作用域校验 + 信任分区与注入防护 + TaskAnchor 任务锚定 + 上下文预算 + 双轴模型路由

1）异构输入统一适配层
解决问题：用户问题、会议文档、WAV 转写、会话历史、RAG 片段和工具结果来源不同，若直接拼进 Prompt，会丢失来源、权限、媒体类型和安全状态
当前做法：不把所有内容转换成自建统一 Token，而是统一登记为 InputArtifact；每个制品带 source、media_type、trust_level、content_ref、checksum、security_status 和 metadata
项目边界：MeetingMind 只保留文本、文档和已经跑通的 WAV 音频；WAV 先由 RabbitMQ + FunASR 形成转写证据，Agent 输入层接收证据引用而不是直接理解原始音频；不接图片、视频或传感器时序数据

输入范围的六项收口（已实现）：
1）严格准入：文本/文档只接受 txt、md、pdf、docx、csv、xlsx、xlsm，音频只接受 WAV；服务端同时校验扩展名、MIME、文件大小和实际内容结构，PDF 检查文件头、Office 检查 OOXML ZIP 关键成员、文本检查编码与二进制 NUL、WAV 检查 RIFF/WAVE、音频帧、采样率、声道和时长。图片、视频、旧版 doc、伪装文件、空文件及传感器文件在进入解析/队列前拒绝
2）ASR 溯源：保存音频 SHA-256、源文件名/MIME/大小、FunASR 及 VAD/标点/说话人模型版本、包版本、设备、时间戳来源、说话人匿名标签、不确定性和处理时延；首次模型原始转写与当前安全/修订文本分开保存，外部会议接口不返回原始未筛选全文
3）状态机：音频证据使用独立 transcript_status，状态限定为 pending、processing、completed、failed，并在会议元数据中记录提交、开始、完成或失败时间；会议业务 status 不再被 ASR Worker 覆盖。只有 completed 且存在安全文本时才创建 asr_evidence 文档和向量块，空结果或全部隔离不会生成“空 RAG 文档”
4）非可信证据筛查：FunASR 的每个句级片段在形成纪要、Agent 上下文或 RAG 索引前执行间接 Prompt Injection 规则检查；命中 block 的片段以 quarantined 状态和内容哈希保留供授权用户复核，但不进入当前正文、纪要初稿、检索块或 citations
5）人工修订版本化：编辑 ASR 片段、删除 ASR 片段或修订完整转写都会增加 transcript_revision/evidence_version，记录修订人、时间、原因和上一版文本哈希；旧 PostgreSQL 向量块和检索缓存先失效，再由当前安全文本重建。若重建没有产生向量块，元数据明确标为 rebuild_required，不伪装成已索引
6）引用式 Agent 输入：InputEnvelope 对音频/文档/检索材料只保留 content_ref、checksum 和经过白名单筛选的来源元数据，例如 meeting_id、speaker、time_offset、task_id、evidence_version、audio_sha256；原始音频、完整文档和完整转写不复制进 Graph State

2）身份与业务作用域校验层
解决问题：用户可在请求中伪造 user_id、meeting_id 或 document_ids，若等到检索或工具阶段才校验，可能造成跨用户串扰和越权访问
当前做法：进入路由前校验 state.user_id 与 access_scope.user_id 是否一致，规范化会议/文档 ID，并检查指定资源是否位于当前用户允许范围；将 can_write、is_admin 和允许范围写入 InputScope
失败策略：身份不一致、资源 ID 非法或明确越权时直接拒绝构建 InputEnvelope，不把可疑请求继续交给模型判断

3）输入安全与信任分区层
解决问题：既要处理用户直接要求忽略系统约束的直接注入，也要处理藏在会话、文档、RAG 片段或工具返回值中的间接注入
当前做法：用户问题在 IntentRouter 之前完成直接注入检查；会话、检索片段和工具结果按制品逐项检查，命中风险的外部制品进入 quarantine，不再进入模型上下文和 citations，其余安全证据仍可继续使用
信任划分：用户问题标记为 user_instruction，但仍不能绕过 ToolPolicy；上传文档、会话历史、检索结果和工具结果分别标记为不可信外部内容，只能作为数据或证据，不能成为新的系统指令
安全边界：当前规则检测是一层纵深防护，不等于“恶意指令免疫”；它不能替代 ACL、参数 Schema、工具权限、HITL、幂等、审计和输出校验

4）意图锚定与任务结构化层
解决问题：长请求常同时包含目标、材料、限制、禁止事项和多个交付物；若只保留原始问题，后续 Planner 容易遗漏要求或在修复/重规划时发生目标漂移
当前做法：建立 TaskAnchor，固定 goal、required_outputs、hard_constraints、forbidden_actions、completion_criteria、ambiguities 和 schema_version
生成过程：输入节点先确定目标、身份/资源硬约束和禁止动作；路由完成后再补充 answer、minutes、todos、controversies 等必需交付物、引用要求、低置信度和未指定检索范围等歧义
下游用途：规划层用 TaskAnchor 约束计划，反思校验层用 completion_criteria 检查是否真的完成用户要求；TaskAnchor 不保存私有思维链

5）上下文组装与预算层
解决问题：历史对话、检索证据和工具结果持续增长时，会造成 Token 超限、噪声放大、旧信息污染和成本失控
当前做法：InputBudget 除字符、计划和工具预算外，新增模型上下文窗口、单节点/整次运行累计 Token、最大模型调用次数和安全余量；所有真实模型请求在统一 LLMService 入口先由 TokenBudgetLedger 预留“估算输入 + 最大输出”，超过模型窗口、节点预算、运行预算或调用次数时不向供应商发请求。响应返回后用供应商 usage 回填真实输入/输出 Token；没有 usage 时继续保留最坏情况预留值，不伪造精确数字
计数边界：可为具体模型注册匹配 tokenizer；明确支持的 OpenAI 模型可使用已安装的 tiktoken；当前 Qwen 环境没有匹配 tokenizer，因此预调用使用 UTF-8 字节数保守上界并明确记录 count_method，再用 15% 模型窗口安全余量抵御消息模板误差。这个结果是工程门禁，不等同于 Qwen 官方 tokenizer 的精确计费数
恢复与并发：同一 Agent Run 的节点和并发工具任务共享一本账；每条决策只保存节点、模型和 Token 数，不保存 Prompt 正文。HITL 确认快照携带账本，恢复时沿用原累计值，缺失或损坏预算快照时拒绝恢复，不能借确认流程获得新预算
轻量组装策略：ContextAssembler 在一次确定性处理内完成四件事：按“证据型工具结果 > 当前检索块 > 最近会话”排序；用规范化内容哈希做精确去重；限制单条长度、总条数和同文档块数；只从允许的只读证据工具中投影 content/chunk_text/text 等白名单字段。TaskAnchor 只投影交付物和硬约束，最多占上下文四分之一，不能挤掉会议证据
旧信息处理：会话记忆按最近轮次优先拆成独立条目，不再把三轮历史合成一个不可拆分字符串；预算不足时按优先级丢弃低优先级旧轮次。长证据只保留前缀并显式标记截断，不再采用“头部 + 陈旧尾部”拼接
五步优化进度：① TokenBudgetLedger 硬门禁；② ContextAssembler 优先级组装；③ 精确去重与同文档多样性上限；④ 最近会话拆分和证据工具白名单投影；⑤ ContextManifest，均已按低复杂度方案实现。ContextManifest 只记录来源引用、内容哈希、原始/纳入长度、截断和丢弃原因，不保存正文，并随普通、SSE 最终事件和批量 Agent 响应返回
刻意不选的复杂方案：当前不做向量近重复检测、LLM 摘要压缩、通用流式增量上下文和跨轮差量缓存。这些方案会增加模型调用、缓存一致性和评测步骤，只有真实长会议基线证明轻量规则不足后再评估

6）任务、复杂度与模型路由层
解决问题：不同请求需要的业务工作流、推理深度和模型成本不同；所有输入都交给同一大模型或同一通用 Agent 会增加延迟、费用和不可预测性
当前做法：在安全与作用域检查之后，分别判断 task_type 和 complexity_level，再生成 workflow_type、model_tier、confidence、complexity_score 和 route_evidence；固定会议任务优先进入确定性工作流，真正复杂任务才进入受限 Planner
降级策略：路由置信度不足时记录 ambiguity 和降级信息，不因模型不确定而扩大资源范围或直接执行外部写操作

本层两个核心数据契约：
1）InputEnvelope（input.v1）：封装请求身份、原始/规范化问题、业务作用域、输入制品、TaskAnchor、路由快照、预算和安全状态，是 Agent 内部契约，不改变现有 HTTP 请求格式
2）TaskAnchor（task-anchor.v1）：封装稳定任务目标、必需产物、硬约束、禁止动作、完成条件和歧义，在规划、恢复和校验过程中保持任务不漂移

本层完整工作流：
文本/文档路径：用户问题 + 身份/资源范围 + 文档引用/会话上下文 → 扩展名/MIME/大小/内容结构准入 → 基础规范化 → 构建 InputArtifact 与 InputEnvelope → 身份和资源作用域校验 → 直接注入检查 → 拒绝恶意用户输入或继续路由 → 任务类型/复杂度/模型档位路由 → 补全 TaskAnchor 与预算 → 检索或工具返回后登记不可信制品 → 间接注入检查与隔离 → ContextAssembler 优先级组装、去重、投影和生成清单 → TokenBudgetLedger 调用前门禁 → 确定性工作流或受限 Planner

音频路径：授权用户上传 WAV → 严格文件准入 → RabbitMQ 任务 pending → ASR Worker processing → FunASR 生成带时间戳/匿名说话人的原始证据 → 逐片段注入筛查 → 原始、安全和隔离证据分区入库 → 安全文本建立 asr_evidence 文档与向量块 → completed；任一关键阶段异常则写 failed，空结果或全隔离结果不建索引

主要异常与处理：
1）空问题、非法 ID、身份不一致、明确越权：确定性拒绝，不调用路由模型
2）直接注入：input_node → prompt_injection_node → rejection_node → END
3）间接注入：隔离命中制品并继续处理剩余证据；如果全部检索证据被隔离，向校验/输出层传递“无安全证据”的失败原因
4）低路由置信度：进入保守 fallback，并保留 route_evidence、ambiguity 和 degradation 信息
5）上下文字符预算不足：ContextAssembler 优先保留任务约束和当前证据，截断单条长证据并丢弃低优先级旧会话，ContextManifest 记录原因；组装后仍超过模型/节点/运行 Token 门禁时拒绝模型调用
6）扩展名、MIME 与内容不一致，或文件为空/超限：在解析、模型调用和消息发布前以 4xx 拒绝
7）WAV 发布失败或 Worker 异常：任务和会议 transcript_status 同步标为 failed，并记录错误类别；不能把失败转写当成空证据继续处理
8）ASR 片段全被隔离或没有识别出语音：处理任务可以完成，但 index.status 为 not_created，Agent/RAG 不会获得该音频的伪证据
9）人工修订后的向量生成失败：保留修订后的权威正文与版本历史，将索引标为 rebuild_required，禁止继续引用旧版本块

与其他链路的边界：
1）与记忆层：输入层只读取当前请求所需的会话上下文并标记来源；跨进程保存 InputEnvelope、TaskAnchor 和图状态属于记忆层的 checkpointer 职责
2）与规划层：输入层提供“要做什么、不能做什么、完成标准是什么”，规划层决定“分几步完成以及每步依赖什么”
3）与工具层：输入层记录 can_write 和禁止动作，真正的工具 Schema、权限、审批、超时、幂等和执行仍由工具层负责
4）与校验层：输入层提供完成条件、证据要求和安全状态，校验层决定 pass、repair、replan、human_review 或 stop
5）与输出层：输入层不直接决定最终 complete/partial/failed/rejected，只向输出层提供结构化原因和降级事实

当前已实现：
1）InputEnvelope、InputArtifact、InputScope、InputBudget、InputSecurity、InputRouting 和 TaskAnchor 的 Pydantic 契约
2）输入优先于路由的真实图路径，以及直接注入拒绝分支
3）用户问题、指定文档、会话、检索片段和工具结果的来源/信任标签
4）间接注入制品隔离，并同步移出上下文与 citations
5）TaskAnchor 接入规划提示与必需输出校验
6）输入契约、越权、直接/间接注入和图级拒绝路径的自动化回归测试
7）文档/WAV 的扩展名、MIME、大小和实际内容联合准入，以及图片/视频/传感器等非目标模态的确定性拒绝
8）ASR Evidence v2：原始/当前转写分区、音频和模型溯源、证据版本、处理状态、人工复核与索引状态
9）ASR 逐片段安全筛查，隔离内容不进入当前正文、纪要草稿和检索索引
10）完成态安全证据自动生成私有 asr_evidence 文档及可检索向量块；空/全隔离/失败结果不创建空索引
11）人工修订递增证据版本，旧块和缓存失效后重建，并向前端显示音频证据状态与隔离提示
12）检索制品的说话人、时间偏移、任务 ID、证据版本和音频哈希进入 InputArtifact 元数据，但正文仍只以引用和校验和登记
13）TokenBudgetLedger 接入统一模型入口：调用前执行模型窗口、节点累计、运行累计和调用次数硬门禁，预留最大输出与安全余量，响应后用真实 usage 校准，并随 Agent/HITL 快照返回可审计决策
14）ContextAssembler 接入 Agent 与独立 RAG 生成路径：最近会话优先、证据来源排序、精确去重、同文档块数限制、证据工具白名单投影、前缀截断和无正文 ContextManifest

本层明确不做：
1）不恢复图片、视频、ROS 或传感器输入，也不建设统一多模态 Token 空间
2）不使用独立过滤 LLM 作为唯一安全边界
3）不对用户原意做不可追踪的语义改写，只做空白规范化与结构化提取
4）不在输入层执行外部工具、保存长期记忆或决定最终答案质量
5）不宣称规则能够检测所有 Prompt Injection，后续仍需真实 Bad Case 测量误报和漏报
6）不接收 MP3/M4A 等依赖额外解码器的音频格式；需要扩展时必须先建立可复现转码、病毒扫描和失败恢复链路
7）不把 FunASR 的 speaker_N 解释为真实人员身份，也不把 completed 等同于“转写准确”或“人工审核通过”
8）本次索引重建以 PostgreSQL/pgvector（或轻量向量列）为权威主链；可选 Milvus 若启用，仍需单独执行/验证同步任务，不能把 PostgreSQL 重建误写成双库已强一致
9）不做需要额外模型调用的上下文摘要，也不做向量近重复、流式增量和跨轮差量缓存；当前只承诺确定性精确去重与字符/Token 双层预算

亮点：
1）安全检查先于模型路由，避免恶意输入先进入路由模型；直接注入拒绝与间接证据隔离采用不同策略
2）用有类型、有来源、有引用的 Artifact 统一异构材料，而不是把业务数据无差别拼接成 Prompt
3）TaskAnchor 将目标、交付物、约束和完成条件贯穿规划与校验，降低长任务目标漂移
4）权限范围和写能力在模型调用前确定，后续模型只能在既定作用域内决策
5）InputEnvelope 使用版本化严格 Schema，并以引用和校验和控制状态体积、来源追踪和后续演进
6）Token 预算不是提示词约定：统一模型入口在网络请求前执行不可绕过的硬门禁，且不把 Prompt 正文写入预算快照
7）上下文选择不是不可见的字符串切片：每个纳入、截断、去重和丢弃决定都进入 ContextManifest，且清单不复制正文

本层尚需通过后续学习确认：
1）逐字段确认 InputEnvelope 与 TaskAnchor 为什么存在、由谁写入、由谁消费
2）确认直接注入、间接注入、普通引用和角色扮演内容的判定边界
3）设计固定 Prompt Injection Bad Case 集，测量规则的误报率、漏报率和隔离后任务完成率
4）用真实长会议集测量轻量策略的证据覆盖率、重复率、旧轮次占比、任务完成率和 Token 消耗，再决定是否需要语义去重或摘要压缩
5）确认 input.v1 的冻结条件；字段语义确认后再进入记忆层并持久化该契约
