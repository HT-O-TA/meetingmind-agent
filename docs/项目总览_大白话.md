# MeetingMind 项目总览（大白话）

## 一句话说明

MeetingMind 是一个“会议资料问答和行动项助手”。它把会议文档或会议录音变成可检索的证据，然后回答问题、生成纪要、提取待办和争议点；如果用户要求写入 Jira，还会先经过权限、风险和人工确认。

它的重点不是“接了多少模型”，而是把一条真实、可追踪、能拒绝危险操作的 AI 应用链路跑通。

## 一次请求怎么走

```text
会议文档 / WAV 录音
        ↓
文档解析，或 RabbitMQ + FunASR 异步转写
        ↓
按说话人和语义切分，保存来源、时间和版本
        ↓
PostgreSQL 关键词检索 + 向量检索（可选 Milvus）
        ↓
融合召回结果，再用 reranker 排序
        ↓
RAG 回答，带引用和权限过滤
        ↓
LangGraph Agent 决定：问答 / 纪要 / 待办 / 争议 / 复杂计划
        ↓
需要外部写入时：工具策略 → 风险判断 → 人工确认 → 执行 → 审计
```

## 六个层次，用人话解释

### 1. 输入预处理层

先确认“谁在问、能看什么、问题是什么、材料从哪里来、材料是否可信”。这一层会生成 `InputEnvelope` 和 `TaskAnchor`，并在进入路由模型前拦截明显的越权和直接注入。

当前实现基本收口，`input.v1` 的设计语义和最小保护动作已经确认并落实；上下文参数仍没有用真实长会议做最终校准。下一步进入记忆层持久化闭环的真实环境验收。

### 2. 记忆层

保存有限的会话上下文，让当前问题能参考最近几轮对话。它不是无限长期记忆，也不应该把所有历史一股脑塞给模型。

当前已经完成本地闭环：固定 `thread_id`/`run_id`/`task_id` 语义，Agent 图支持持久 checkpoint，短期会话保持固定窗口和 LRU，长期事实具备 PostgreSQL 主库、冲突覆盖、删除和 outbox 接线。默认仍可用本地/进程内适配器，生产多副本还要做真实 PostgreSQL、RabbitMQ、Milvus、Neo4j 演练。

技术细节见[记忆层](./架构解析/记忆层.md)。

### 3. 规划推理层

根据问题决定走固定流程，还是先拆成多个任务再执行。简单问题直接回答，会议纪要和待办走结构化流程，复杂问题走受限 Planner。

### 4. 工具调用执行层

工具必须有明确参数 Schema、权限、风险等级、超时、幂等和审计。当前正式外部写目标只有 Jira Cloud；创建或更新 Issue 必须人工确认。

### 5. 反思校验层

检查回答是否真的产出了要求的内容、是否缺少引用、结构是否符合 Schema。发现小问题可以修复，需要重新思考时才重规划。

### 6. 输出层

把答案、纪要、待办、引用、降级原因、预算和任务状态整理成稳定的 API 返回值。输入层只提供事实和约束，不提前替输出层决定最终是 complete、partial 还是 failed。

## 对外 API

- `/api/v1/users`：注册、登录、当前用户。
- `/api/v1/meetings`：会议和发言记录。
- `/api/v1/documents`：文档上传、解析和更新。
- `/api/v1/todos`：待办事项。
- `/api/v1/rag/ask`：带 ACL 和引用的 RAG 问答。
- `/api/v1/agents/query`：Agent 普通查询；另有 SSE 和批量接口。
- `/api/v1/agents/confirmations/*`：人工确认和恢复执行。
- `/api/v1/tasks`：文档/音频异步任务状态。
- `/api/v1/feedback`：反馈和 Bad Case 闭环。

开发/测试环境才注册 `/api/v1/trace`，生产环境不暴露内部 Trace 路由。

## 当前完成度

| 事项 | 当前状态 | 不能过度解读的地方 |
|---|---|---|
| 输入契约和安全边界 | 已实现，有契约测试 | 真实攻击分布还没有校准 |
| RAG 主链 | 已实现，有 ACL、引用和降级字段 | 缺冻结的真实会议真值集和正式指标 |
| Agent 主链 | 已实现固定 LangGraph 工作流 | 真实业务端到端效果还未形成基线 |
| RabbitMQ/Worker | 已做确认、重试、DLQ、幂等测试 | 不是多节点高可用容量证明 |
| ASR | WAV → FunASR → 证据入库链路已跑通 | 公开单句烟测不代表多人会议 CER/DER |
| LoRA/QLoRA | 合成待办抽取实验已完成 | 合成数据不能代表真实会议质量 |
| 部署和 CI | 本机 Compose、镜像和门禁已有证据 | TLS、备份、Secret Manager、生产 HA 未验收 |

## 旧文档已经合并成什么

原来的阶段文档没有全部重复搬进主文档，而是压缩成下面这条“项目怎么一步步收敛”的时间线。需要看细节时，再打开对应原文。

| 原阶段 | 用大白话说，它记录了什么 |
|---|---|
| 01 双轴模型路由 | 用“任务类型 + 问题复杂度”决定模型档位，不让所有问题都调用最贵模型 |
| 02 主链路真实性审计 | 清理没有业务闭环的接口、Service、Agent 和假工具 |
| 03 RAG 主链路 | 关键词召回和向量召回合并，再重排并返回引用 |
| 04 Agent 阶段 0 | 固定 LangGraph 主图和最小可运行测试基线 |
| 05 RAG 权限与评估 | 把 ACL、路由、结构化输出和离线评估接起来 |
| 06 Agent 工具安全 | 工具 Schema、风险、人工确认、幂等和审计形成闭环 |
| 07 RabbitMQ | 处理确认、重试、死信、任务状态和重复消费 |
| 08 ASR | WAV 转写、时间戳/匿名说话人、证据隔离和修订版本 |
| 09 LoRA/QLoRA | 用合成待办数据完成可复现实验，但不冒充真实会议效果 |
| 10 部署与 CI | Compose、Worker、固定 Demo、依赖锁和自动化门禁 |
| 11 深度瘦身 | 删除多智能体、MCP、知识图谱等没有证据的旁支 |
| 12 双轮审查 | 全仓检查真实 HTTP、队列并发和四个固定 Demo |
| 13 输入预处理 | 收敛 `InputEnvelope`、`TaskAnchor`、信任分区和上下文预算 |

六链路架构的第一、第二版是设计演进记录，第三版才是当前口径；PatchAlign-Cpp 是另一个项目，不能当作 MeetingMind 的未完成模块。

## 项目明确不再做什么

当前不恢复知识图谱、MCP、多智能体、图片/视频多模态、复杂长期记忆、多个未实现的企业平台适配器。这些内容不是“忘了做”，而是因为没有明确业务闭环或可核验数据，所以从主线移除。

## 接下来做什么

1. 完成服务重启后的 HITL 节点级恢复验收，并确认外部工具不会重复执行。
2. 多副本生产部署前接入共享 PostgreSQL saver，补并发、保留、删除和备份恢复演练。
3. 用真实/脱敏长会议验证上下文覆盖率、重复率、任务完成率和 Token 消耗。
4. 再决定是否需要摘要、语义去重、长期记忆或更复杂的 Agent 编排。
