# 证据与限制

## 已有证据

- `backend/tests/contracts/` 覆盖输入契约、上下文预算、权限、规划门禁、工具确认、幂等、队列恢复和输出结构。
- 冻结评测集包含 28 场会议、100 条人工复核任务，并记录版本、Manifest 和 SHA-256。
- 云端受控评测完成 100/100 条请求，JSON 有效率 100%、请求失败率 0%。
- QA 引用 Precision 97.5%、Recall 22.2%；待办字段 F1 71.3%；约束字段 F1 46.7%。
- 四种检索方案完成会议内对比；文本去重后 Hybrid 的 Recall@5 最高，Reranker 没有超过 Hybrid。
- 五分钟固定演示已跑通 HTTP 主链、权限拒绝、工具确认和队列恢复。
- ASR 有公开 WAV 单句的真实 GPU 烟测；LoRA/QLoRA 有单卡运行记录。

## 指标口径

- QA 检索已经知道目标会议 ID，只在该会议内部寻找证据，属于 `within_meeting_oracle`，不能表述为全库召回率。
- 待办和约束评测输入是候选项，衡量“是否保留和字段如何规范化”，不是从整场会议重新发现全部项目。
- 生成对比每种检索方法只运行 10 条 QA，定位为链路 smoke，不用于证明某种方法的答案质量更好。
- Prompt Injection 的 25 条样本是合成回归集，只能证明当前规则没有回归。
- ASR 单句结果不能代表多人长会议 CER/DER。
- LoRA/QLoRA 使用合成待办数据，不能代表真实会议泛化能力。

## 尚未形成证据

- 全库、跨会议检索与无答案识别的正式基线；
- 足量人工 QA 答案正确率和引用充分性评分；
- 真实多人长会议 ASR 指标；
- 真实 Jira 站点写入、回查和权限演示；
- Milvus/Neo4j 长期记忆投影与对账恢复；
- 多节点高可用、生产容量、灾备和长期在线稳定性；
- 真实攻击分布下的注入误报率与漏报率。

## 对外可以怎样描述

可以说：

> 基于 28 场公开/脱敏会议构建 100 条人工复核冻结任务，完成会议内检索、引用、待办/约束规范化评测，以及 HTTP、权限、工具确认和队列恢复演示。

不能说：

> 已在 100 场会议或企业生产环境验证，具备生产级泛化、高可用和完整长期记忆能力。
