# 固定五分钟演示（当前版本）

这份演示把四件最重要的事串在一起：正常请求能走通、没权限会被拒绝、外部写操作必须确认、队列失败后能恢复。每一步都有 JSON 结果和 stdout/stderr 日志，方便复盘。

## 演示流程

| 时间 | 演示内容 | 看到什么 |
| --- | --- | --- |
| 0:00–1:40 | HTTP 主链 | 注册/登录、创建会议、上传文本、检索和待办；再用另一个用户访问，得到 403 且不泄露列表 |
| 1:40–2:20 | 工具确认 | `jira_create_issue` 在未确认时返回 `confirmation_required`，确认后策略放行；不真的写 Jira |
| 2:20–4:00 | 队列恢复 | 注入一次确定性失败，消息按重试/死信规则处理，随后恢复消费 |
| 4:00–5:00 | 查看证据 | 打开 `manifest.json`、三个 JSON 报告和日志，核对状态与耗时 |

## 一条命令

在仓库根目录执行：

```powershell
python scripts/demo_five_minute.py --base-url http://127.0.0.1:8000
```

默认输出到 `artifacts/five-minute-demo/`：

- `manifest.json`：总状态、覆盖场景、每步耗时和限制；
- `01_http_business_flow.json`：正常路径、权限拒绝和业务队列证据；
- `02_tool_confirmation.json`：确认前拦截、确认后放行；
- `03_queue_recovery.json`：重试与死信恢复；
- `*.stdout.log`、`*.stderr.log`：原始运行日志。

如果本地 API、PostgreSQL、Redis 或 RabbitMQ 没启动，HTTP/队列步骤会标记失败或不完整，而不是伪造成功。工具确认步骤仍可单独运行：

```powershell
python backend/scripts/demo_tool_confirmation.py --output artifacts/five-minute-demo/02_tool_confirmation.json
```

服务启动后，可用同一套脱敏问题采集端到端指标（先设置登录后的 Bearer Token）：

```powershell
$env:MEETINGMIND_BEARER_TOKEN = "<token>"
python scripts/measure_agent_runtime.py --output artifacts/runtime-benchmark.json --repeat 3
```

只有 API 返回供应商 usage，并且同时传入 `--input-price-per-1k` 与 `--output-price-per-1k`，报告才会计算成本；否则成本保持 `null`。

## 证据边界

- 这是固定可重复演示，不等于真实长会议效果证明。
- 工具确认只证明策略门禁生效，没有真实 Jira 写入；真实租户需要另做隔离测试。
- 队列恢复是单节点、确定性故障注入，不能替代生产多副本演练。
- 是否能在五分钟内完成取决于本地服务和网络；manifest 会留下实际耗时。
