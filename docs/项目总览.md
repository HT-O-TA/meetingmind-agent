# MeetingMind 项目总览

## 项目定位

MeetingMind 是一个会议知识 Agent：将会议文档或 WAV 音频处理成可检索证据，支持带引用问答、纪要、待办和约束提取，并通过权限、人工确认、幂等和审计控制外部工具调用。

它是面向企业会议场景完成的个人工程项目，已经具备可运行、可测试、可追溯的本地闭环，但没有真实企业生产流量和高可用运行证明。

## 主链路

```text
会议文档 / WAV 音频
        ↓
文档解析，或 RabbitMQ + FunASR 异步转写
        ↓
按说话人和语义切块，保存来源、时间与版本
        ↓
BM25 + Dense 检索，按需使用 Reranker
        ↓
权限过滤与引用组装
        ↓
LangGraph 路由、规划和结构化生成
        ↓
高风险写操作：策略检查 → 人工确认 → 幂等执行 → 审计
```

## 六层架构

### 1. 输入预处理层

把用户、会话、文档、检索和工具结果统一为版本化 `InputEnvelope`。`TaskAnchor` 固定任务目标、必需输出、禁止动作、否定条件和阈值；来源、权限、安全状态和 Token 预算随任务传递，避免后续节点重新猜测。

### 2. 记忆层

运行检查点、短期会话和长期事实分开处理。PostgreSQL 保存权威事实，Redis 用于缓存和短期状态，Outbox 与 RabbitMQ 为索引同步提供可靠边界。Milvus/Neo4j 的具体长期记忆投影器尚未完整接入，因此生产开关默认关闭。

### 3. 规划推理层

简单任务走固定工作流，复杂任务才进入受限 Planner。计划必须满足结构化 Schema、工具白名单、依赖无环、步骤/调用/Token 上限；重复失败会熔断，否定和阈值约束会在执行前复核。

### 4. 工具调用层

工具执行前校验参数、用户权限和风险等级。高风险写操作必须经过 HITL；幂等键避免重复副作用，审计表保留执行结果。Jira 接口目前是受控接入边界，不宣称已完成真实生产接入。

### 5. 输出层

统一返回答案、引用、待办、约束、任务状态和降级原因。引用只能指向模型实际看到的片段；证据不足时允许拒答或返回部分完成。

### 6. 反思与恢复层

质量门禁检查必需输出、引用和结构。需要时才重规划；Agent checkpoint 支持任务恢复，RabbitMQ 负责确认、有限重试、死信和恢复演示。

## 主要技术组件

| 组件 | 定位 |
|---|---|
| FastAPI | HTTP API |
| LangGraph | Agent 状态图和节点编排 |
| PostgreSQL | 用户、会议、文档、待办、审计和长期事实 |
| Redis | 缓存与短期状态 |
| RabbitMQ | 文档、音频、向量和记忆事件的异步任务 |
| Milvus | 文档向量检索 |
| BGE-M3 | 本地 Embedding |
| bge-reranker-v2-m3 | 本地重排 |
| Qwen API | 规划和结构化生成 |

## 当前证据

- 冻结评测集：28 场公开/脱敏会议，100 条人工复核任务，其中 QA 40、待办 30、约束 30。
- 云端受控评测：100/100 返回有效 JSON，请求失败率 0%，总 Token 37,171。
- QA 引用 Precision 97.5%、引用 Recall 22.2%；待办字段 F1 71.3%；约束字段 F1 46.7%。
- 检索对比属于已知会议范围内排序：文本去重后 Hybrid 的 Recall@5 最高，Reranker 没有超过 Hybrid。
- 固定演示已覆盖 HTTP 正常路径、跨用户/部门权限拒绝、工具确认和队列恢复。
- 核心契约测试的冻结报告为 120 passed。

指标的完整定义和限制见[真实会议评测收口](./真实会议评测收口.md)与[证据与限制](./证据与限制.md)。

## 尚未证明的能力

- 全库、跨会议检索效果；
- 真实多人长会议 ASR 的 CER/DER；
- 真实 Jira 写入与企业权限体系；
- Milvus/Neo4j 长期记忆投影闭环；
- 生产级并发、容灾、TLS、备份和高可用；
- 真实攻击分布下的 Prompt Injection 安全率。
