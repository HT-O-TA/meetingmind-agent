# 真实会议候选标注：人工复核说明

机器整理已经完成，复核人员不需要再打开原始目录找文件，直接从下面两个文件开始：

- `backend/evaluation/datasets/meetingmind_real_v1_sources.jsonl`：8 个 AliMeeting 会议源记录；
- `backend/evaluation/datasets/meetingmind_real_v1_candidates.jsonl`：VCSUM 的问题、答案、引用和待办候选；
- `backend/evaluation/datasets/meetingmind_real_v1_review_manifest.json`：数量、哈希、限制和复核清单。

## 复核顺序

1. 先确认问题是否真的能从对应会议回答；不能回答的记录标记为 `reject`。
2. 对保留记录逐条查看 `citations`，确认引用原文真的支持答案；不完整时补充或替换引用。
3. 查看 `todo_candidates`，把长句改成一个明确动作，补齐负责人、截止时间和状态；没有明确动作就删除。
4. 查看 `constraints`，确认“不要/不得/除非”、预算阈值、范围限制和前后修改是否准确。
5. 复核通过后，将记录的 `annotation_status` 改为 `gold`，同时保留 `reviewer`、`reviewed_at` 和 `review_note`。

## 通过标准

- 每个答案至少有一个能直接支持关键事实的引用；
- 每个待办都有原文证据，负责人或截止时间缺失时明确留空，不猜测；
- 否定、阈值和“改为/取消”不能被摘要省略；
- 同一会议的所有记录保持同一个 `meeting_id`，之后按会议切分数据集；
- 只有 `gold` 记录才进入正式 `evaluation.v1` 指标报告。

## 当前边界

这批文件是 `silver` 候选，不是最终真值。问题由规则生成，待办和约束是低置信度启发式初筛；人工复核完成前，不应报告正式待办 F1 或真实任务完成率。
