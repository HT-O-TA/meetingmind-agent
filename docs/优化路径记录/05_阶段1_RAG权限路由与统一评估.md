## 1. 阶段结论

当前可独立完成的阶段 1 工程项已经闭环：

- 正式检索仍是 PostgreSQL 关键词召回 + Dense + 加权融合 + 可选 Reranker；
- RAG 与 Agent API 都必须认证，并把用户 ACL 下推到每一路召回和 PostgreSQL 回查；
- PostgreSQL 对文档公开性、上传者、部门、显式范围和软删除状态拥有最终裁决权；
- 检索缓存按完整 ACL 范围隔离，query-only 语义缓存不再返回检索结果；
- `RouteDecision` 成为唯一正式路由契约，包含任务、复杂度、模型档位、执行模式、置信度、子任务、阈值来源和降级动作；
- RAG 回答固定返回引用、阶段时延、来源、降级信息和 Schema 版本；
- 纪要、决策、待办、争议、执行计划、反思和工具调用外壳已有 Pydantic Schema；

## 2. ACL 为什么必须有两层

```text
用户 JWT
→ AccessContext
→ Milvus：只下推可无损表达的 meeting/document 显式范围
→ PostgreSQL：公开文档 OR 本人上传 OR 同部门
               AND 文档/Chunk 未软删除
               AND 显式 meeting/document 范围
→ 返回正文
```

Milvus 元数据不能完整表达“公开、上传者、部门”三者的业务 ACL。若只在 Milvus 过滤，会错误排除其他部门的公开文档；若只召回后直接返回，又可能泄漏私有文档。因此 Milvus 负责缩小候选，PostgreSQL 回查负责最终授权和正文一致性。

缓存也属于权限边界。相同问题由两个用户查询时，候选 ID 不能共享；即使 ACL 缓存命中，仍需回 PostgreSQL 重验权限和软删除，防止缓存期间权限或删除状态变化。

## 3. 唯一路由契约

正式输出为 `RouteDecision(route.v1)`：

```text
task_type + complexity_level
→ ModelRouter
→ model_tier + model_name
→ execution_mode
→ confidence / task_confidence / complexity_confidence
→ sub_tasks / decision_trace / degradation_actions
```

低任务置信度进入 `fallback`，禁止把不确定意图升级为外部写操作；低复杂度置信度只降低执行复杂度，不改变已经确定的业务任务。阈值来自配置，但当前标记为 `config_provisional_until_route_eval`；离线评估只能给出推荐值，不会自动修改生产配置。

旧 `route_instruction.py` 现在只是兼容导入，实际定义和双轴模型表分别只有 `RouteDecision` 与 `ModelRouter` 两个所有者。

## 4. 结构化输出和修复边界

结构化业务结果统一保留：

- `schema_version`、`prompt_version`、`model_version`；
- `source_id`、`source_type`、`speaker`、`timestamp`；
- `uncertainties`、`degradation_info`。

JSON 修复只允许两种确定性转换：去掉 Markdown 代码围栏、删除对象/数组尾逗号。修复后仍必须通过 Pydantic；缺失必填业务字段不会被猜测补齐，而是进入有限重试或确定性业务修复。

工具调用已先验证 `{tool_name, arguments}` 外壳，再进入 ToolPolicy。具体工具参数 Schema、审计和幂等属于阶段 2。

## 5. 统一离线评估

合成样例只验证命令：

```bash
cd backend
python3 scripts/evaluate.py \
  --allow-synthetic \
  --dataset evaluation/datasets/sample_eval.jsonl \
  --output evaluation/reports/sample_report.json
```

输出同时生成 JSON 和 Markdown，覆盖：

| 分区 | 指标 |
|---|---|
| Retrieval | Recall@K、MRR、nDCG@K |
| Generation | 词面 Faithfulness/Answer Relevancy 代理、引用准确率 |
| Extraction | 字段 Precision、Recall、F1、JSON 合法率 |
| Tool | 选择、参数、成功率、HITL 触发准确率 |
| Route | 任务/复杂度准确率、fallback 率、阈值建议 |
| System | 平均/P95 时延、顺序吞吐代理、错误率、Token、成本 |

`evaluation/regression_thresholds.json` 是待真实 Validation 集校准的验收目标，不是已达到的基线。真实数据回归时显式使用 `--thresholds ... --enforce-thresholds`。

## 6. RAG API 契约 Demo

启动后先注册/登录取得 Bearer Token，再调用：

```bash
curl -X POST http://127.0.0.1:8000/api/v1/rag/ask \
  -H 'Authorization: Bearer <token>' \
  -H 'Content-Type: application/json' \
  -d '{"question":"会议决定了什么？","top_k":5,"use_llm":false}'
```

响应的 `data` 固定包含 `schema_version=rag.v1`、`citations`、`retrieval_stage_metrics`、`degradation` 和 `provenance`。未认证请求返回 401；没有知识库内容时返回带 `no_retrieval_results` 的可解释降级，而不是伪造答案。
