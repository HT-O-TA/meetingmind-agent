## 1. 结论摘要

本次静态审计覆盖：

| 层级 | 模块数 | 正式主链路 | 可选增强 | 开发/评测 | Mock/骨架 | 待停用 |
|---|---:|---:|---:|---:|---:|---:|
| API Router | 27 | 8 | 7 | 8 | 2 | 2 |
| Service | 55 | 30 | 9 | 4 | 4 | 8 |
| Agent | 42 | 17 | 11 | 3 | 3 | 8 |
| **合计** | **124** | **55** | **27** | **15** | **9** | **18** |

最重要的真实性结论：

1. `backend/app/api/v1/router.py` 无条件注册了 27 个 Router，没有正式、可选、开发环境三类边界。
2. 当前可确认的 RAG HTTP 入口是 `POST /api/v1/rag/ask`，调用 `RAGService -> VectorSearchService -> BM25 + Milvus Dense -> Fusion -> Reranker`；Sparse 策略 B 仍残留在底层，但配置默认关闭。
3. 当前可确认的 Agent HTTP 入口是 `POST /api/v1/agents/query`，调用 `AgentService -> create_agent_graph -> AgentNodes`。
4. `route_instruction.py` 没有被其他运行模块或测试引用，目前是未接线骨架，不能描述成“统一路由指令已落地”。
5. `enterprise_tools.py` 中飞书、Jira、Notion、Email 客户端返回固定 ID 和固定成功结果，是明确 mock；不能作为真实企业写入证据。
6. `perception_pipeline.py` 中图片、音频、视频关键路径仍抛出 `NotImplementedError`，不能描述成真实多模态闭环。
7. `tests.py` 使用 `f:/project/meetingmind/backend` 硬编码路径，当前 Linux 环境不可复现，也不应作为生产 API 注册。
8. 只有少数 Router 文件出现用户鉴权依赖；`rag.py`、`agents.py`、`todos.py`、`memory.py`、`mcp.py` 等核心或高风险入口目前没有统一鉴权。
9. `ENABLE_MCP_SERVER` 虽已定义，但 `main.py` 当前按“能否导入 MCP”决定挂载，没有使用该开关控制启动。
10. “正式主链路”表示路线决定保留，不代表已经通过运行测试；运行真实性需要在阶段 0 的核心测试基线中单独验证。

## 2. 分类口径

| 分类 | 判定口径 | 当前动作 |
|---|---|---|
| **正式主链路** | 直接支撑会议、文档、RAG、Agent、安全或异步主闭环，并且已有明确调用入口 | 保留；下一步补齐测试、Schema、鉴权和失败边界 |
| **可选增强** | 有实现和岗位价值，但不是第一阶段默认必经路径 | 保留代码；通过配置或环境显式开启 |
| **开发/评测接口** | 用于调试、评估、Prompt 管理或内部观测，不应作为生产公开 API | 仅在 development/test 注册，补管理权限 |
| **Mock/骨架** | 返回模拟结果、关键方法未实现、未接线或无法在当前环境运行 | 禁止宣传为已实现；等待真实接入或移除 |
| **待停用** | 重复、废弃、无引用或偏离当前唯一主线 | 先关闭入口，再做引用分析和回归后删除 |

分类依据包括：Router 注册、静态 import 引用、配置默认值、明确的 TODO/Deprecated/NotImplemented 标记、固定 mock 返回和现有测试引用。动态导入可能无法由静态引用完全覆盖，因此本表是阶段 0 的去留决策基线，不替代运行测试。
