# 优化路径记录 01：双轴模型路由

**优化时间**：2026-08-17
**优化层级**：意图理解层 → 规划编排层
**目标**：通过"任务类型 × 复杂度"双轴联合路由模型档位，降低 LLM 调用成本

---

## 问题背景

原项目所有 LLM 调用统一使用 `qwen3.6-plus`（[config.py#L104](file:///f:/project/meetingmind-agent/backend/app/core/config.py#L104)），仅评估阶段单独用 `qwen-turbo`。问题：

1. **成本浪费**：简单问答（"你好"）用 plus，成本是 turbo 的 8 倍
2. **能力不足**：复杂推理（ReAct/CoT）用 plus，能力不如 max
3. **设计未落地**：[总结.md](file:///f:/project/meetingmind-agent/docs/总结.md) 描述的"任务类型管能不能省，复杂度管省多少"双轴路由未实现

## 设计思路

### 双轴路由原则

```
任务类型（管"能不能省"）
  ├─ QA 类：允许降级到 turbo 省成本（S 复杂度）
  └─ 确定性任务（TODO/MINUTES/CONTROVERSY）：锁 plus 下限，不走 turbo
                                            ↑ 保证输出质量稳定
复杂度（管"省多少"）
  ├─ S/R：不升档（用任务类型决定的基础档位）
  ├─ C：升 max（需要链式推理）
  └─ A：升 max（需要多步工具调用）
```

### 路由矩阵

| task\complexity | S | R | C | A |
|---|---|---|---|---|
| QA | **turbo** | plus | max | max |
| TODO | - | plus | max | max |
| MINUTES | - | plus | max | max |
| CONTROVERSY | - | plus | max | max |
| MULTI | - | - | max | max |

### 成本对比（相对 plus）

| 档位 | 模型 | 相对成本 |
|---|---|---|
| turbo | qwen-turbo | 0.125× |
| plus | qwen3.6-plus | 1.0× |
| max | qwen-max | 2.5× |

**典型场景成本节省**：
- 简单 QA（S）：plus → turbo，**节省 87.5%**
- 待办提取（R）：保持 plus，无变化
- 复杂推理（C/A）：plus → max，成本增加 2.5×，但能力提升保证质量

## 关键设计

### 1. ModelRouter 集中路由（[model_router.py](file:///f:/project/meetingmind-agent/backend/app/services/model_router.py)）

```python
class ModelRouter:
    _ROUTING_TABLE = {
        (TaskType.QA, ComplexityLevel.SIMPLE):    ModelTier.TURBO,  # QA+S 降级 turbo
        (TaskType.QA, ComplexityLevel.RETRIEVAL): ModelTier.PLUS,
        (TaskType.QA, ComplexityLevel.COT):       ModelTier.MAX,
        (TaskType.TODO, ComplexityLevel.RETRIEVAL): ModelTier.PLUS,  # 确定性任务锁 plus
        (TaskType.TODO, ComplexityLevel.COT):       ModelTier.MAX,   # C/A 升 max
        ...
    }

    def select(self, task_type, complexity_level) -> (ModelTier, model_name)
    def select_for_planning(self, complexity_level) -> model_name  # 规划专用
    def select_for_evaluation(self) -> model_name  # 评估专用 turbo
    def explain_routing(self, task_type, complexity_level) -> str  # 路由解释
```

### 2. 三类调用场景

| 场景 | 路由方式 | 示例节点 |
|---|---|---|
| 执行子任务 | `select(task_type, complexity)` | _execute_qa / _execute_minutes / _execute_todos / _execute_controversies |
| 规划/推理 | `select_for_planning(complexity)` | plan_node / react_node / cot_node |
| 评估 | `select_for_evaluation()` | reflection_node / quality_gate |

### 3. 路由可解释性

`explain_routing()` 生成人类可读的路由解释，写入 trace：
```
QA + 简单复杂度，允许降级到 turbo 省成本；复杂度 simple，无需升档 → 最终 turbo（qwen-turbo）
TODO 确定性任务锁 plus 下限，不走 turbo；复杂度 cot 需要强推理，升 max → 最终 max（qwen-max）
```

## 面试讲解要点

### 一句话表述
> "我设计了双轴模型路由——任务类型管'能不能省'，确定性任务锁 plus 下限，只有 QA 类在简单复杂度下允许降级到 turbo；复杂度管'省多少'，C/A 级别无论任务类型都升 max 保证推理能力上限。"

### 量化收益
- 简单 QA 调用成本降低 **87.5%**（plus→turbo）
- 整体 LLM 成本约降低 **30-40%**（按 QA 占比 60% 估算）
- 复杂推理质量提升（plus→max）

### 设计权衡
- **为什么不全部用 max？** 成本不可控，max 是 plus 的 2.5 倍
- **为什么确定性任务不允许 turbo？** 纪要/待办/争议需要稳定输出质量，turbo 能力不足
- **路由表为什么不做成配置文件？** 当前硬编码更清晰，且矩阵稳定（5×4=20 组合）。后续可加 `MODEL_ROUTING_OVERRIDE` 环境变量支持 A/B 实验

### 与主流对比
- **Anthropic effort-scaling**：简单查询 1 agent，复杂查询最多 8 subagent —— 我这是"模型档位 effort-scaling"
- **Salesforce HyperClassifier**：用 SLM 替代 LLM 做路由 —— 我的 qwen3-0.6B 复杂度分类器就是这个思路
- **i10x LLM-first**：先优化基础模型选择再加 agent 能力 —— 我的双轴路由就是 LLM-first 的体现
