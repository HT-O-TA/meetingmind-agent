# 优化路径记录 01：双轴模型路由

日期：2026-08-17（2026-08-26 按深度瘦身后代码重写）

## 1. 当前目标

`ModelRouter` 只做一件事：根据“任务类型 × 复杂度”选择 `turbo / plus / max` 档位和对应模型名。

它不估算虚构成本，不宣称未评测的节省比例，不兼任质量评估器，也不创建 ReAct/CoT 执行分支。成本和效果只能由真实调用记录与冻结评测集证明。

## 2. 路由矩阵

| task \ complexity | SIMPLE | RETRIEVAL | COT | AGENT |
|---|---|---|---|---|
| QA | turbo | plus | max | max |
| TODO | plus（回退） | plus | max | max |
| MINUTES | plus（回退） | plus | max | max |
| CONTROVERSY | plus（回退） | plus | max | max |
| MULTI | plus（回退） | plus（回退） | max | max |

没有显式匹配的组合统一回退到 `plus`，不因为输入缺失而意外选择最强或最弱模型。

## 3. 代码边界

当前实现位于 `backend/app/services/model_router.py`，公开方法只有：

```python
tier, model_name = router.select(task_type, complexity_level)
planning_model = router.select_for_planning(complexity_level)
```

- `select()` 用于 QA、纪要、待办和争议点等业务节点；
- `select_for_planning()` 在 `COT/AGENT` 复杂度选 `max`，其余选 `plus`；
- 档位对应的真实模型名由 `MODEL_TURBO_NAME`、`MODEL_PLUS_NAME`、`MODEL_MAX_NAME` 配置；
- 质量门禁独立使用 `QUALITY_GATE_MODEL`，不属于业务路由。

深度瘦身已删除旧文档中的 `select_for_evaluation()`、`explain_routing()`、相对成本表、ReAct/CoT 专用节点和未验证的“整体降本 30%-40%”说法。

## 4. 设计权衡

1. 使用规则矩阵而不是再调一次 LLM：结果可重现，也不引入额外延迟。
2. 矩阵保持在代码中：当前规模小且变更需要代码审查，没有动态配置中心的实际需求。
3. `COT` 只是复杂度标签：它表示需要更强的规划能力，不表示向用户暴露私有思维链。
4. 路由是假设而不是收益证据：如果要声称降本或质量改善，必须冻结请求集，记录模型版本、Token、价格、延迟和业务指标。

## 5. 验证方式

```python
from app.agents.state import ComplexityLevel, TaskType
from app.services.model_router import get_model_router

router = get_model_router()
assert router.select(TaskType.QA, ComplexityLevel.SIMPLE)[0].value == "turbo"
assert router.select(TaskType.TODO, ComplexityLevel.RETRIEVAL)[0].value == "plus"
assert router.select(TaskType.QA, ComplexityLevel.AGENT)[0].value == "max"
```

代码级路由验证放在 Agent 与契约测试中；真实收益在冻结数据和调用价格表齐备前保持“未验证”。

## 6. 面试表述

> 我用任务类型和复杂度做可重现的模型档位路由：简单 QA 允许使用 turbo，检索与结构化业务默认 plus，复杂规划选 max。路由器只作决策，不伪造成本收益；收益需用冻结请求集和真实 Token/价格数据验证。
