# MeetingMind 项目真实总结

## 一、项目概述

MeetingMind 是一款基于 **RAG（检索增强生成）** 和 **Agent** 技术构建的企业级智能会议助手系统。项目采用前后端分离架构，后端基于 FastAPI + SQLAlchemy 2.0 async 构建异步服务，前端基于 Vue3 + Pinia 实现交互式界面。

**核心定位**：面向企业会议场景，提供会议文档处理、智能问答、纪要生成、待办事项抽取、争议点分析等一站式 AI 辅助能力。

**技术栈概览**：
- **后端**：Python、FastAPI、SQLAlchemy 2.0 async、LangGraph、PostgreSQL、pgvector、Redis、RabbitMQ、FastMCP、Locust、RAGAS
- **前端**：Vue3、Pinia、Axios、Element Plus、Vue Router
- **AI 模型**：BGE-M3（向量化）、BGE-Reranker（精排）、Qwen3-0.6B（复杂度分类）、Qwen-turbo/plus/max（模型路由）

```
         ▼                     ▼                     ▼
┌───────────────┐    ┌───────────────┐    ┌───────────────┐
│   RAG检索层   │    │   Agent层     │    │  异步任务层   │
│ BM25+BGE-M3   │    │ 4级复杂度路由 │    │  RabbitMQ    │
│ 三路召回+RRF  │    │  ReAct推理    │    │   Worker     │

└─────────────────────────────────────────────────────────────────┘
```

### 2.2 RAG 检索架构

```
查询 → 三路召回 → RRF融合 → Reranker精排 → 最终结果
       ↓
  ├─ BM25（关键词检索）
  ├─ BGE-M3稠密（语义向量）
  └─ BGE-M3稀疏（lexical_weights）
```

### 2.3 Agent 工作流架构

```
用户输入 → 复杂度分类 → 路由决策
              ↓
    qwen3-0.6B分类器
              ↓
    ┌─────────────────────┐
    │ 4级复杂度分级       │
    │ S: Simple (0-0.3)  │ → 直接回答
    │ R: Retrieval       │ → RAG单轮检索
    │     (0.3-0.5)      │
    │ C: CoT (0.5-0.75)  │ → 思维链推理
    │ A: Agent (0.75-1)  │ → ReAct循环
    └─────────────────────┘
    
    + Plan模式：多任务检测 → 任务拆解 → 子任务路由 → 结果汇总
```

### 2.4 异步任务处理架构

```
文档上传 → 创建任务 → 入队 → Worker消费 → 状态追踪 → 结果存储
              ↓
         Redis存储任务状态
              ↓
         RabbitMQ队列
              ↓
         文档处理Worker
              ↓
         解析 → 分块 → 向量化 → 存储
```

## 四、项目技术亮点

### 4.1 SPEAKER_AWARE_HYBRID 分块策略

**技术说明**：针对会议文档设计的混合分块策略，融合说话人识别与语义连贯性。

**核心特点**：
- 优先保持段落/语义连贯性
- 说话人切换作为"加分项"而非"强制项"
- 严格遵守最大/最小块大小限制
- 过滤语气词和纯噪音内容
- 无说话人信息时自动降级为纯语义分块

**实验验证**：
- 信息密度提升至91.79%
- 语义完整性100%（无句子切断）
- 平均块大小102字符，适合embedding

### 4.2 四级复杂度自适应路由

**技术说明**：基于Qwen3-0.6B的问题复杂度分类系统，实现智能推理路由。

**核心特点**：
- S级（0-0.3）：Simple QA，直接回答单事实问题
- R级（0.3-0.5）：RAG检索，需要查资料的事实型问题
- C级（0.5-0.75）：CoT推理，需要1-2步推理
- A级（0.75-1.0）：ReAct循环，多跳推理+工具调用

**策略回退**：ReAct失败→CoT→RAG，检测连续相同输出自动切换规则路由

### 4.3 三路召回融合架构

**技术说明**：结合BM25关键词检索、BGE-M3稠密向量和稀疏向量的多路召回策略。

**核心特点**：
- BM25：精准匹配关键词，召回率59.6%
- BGE-M3稠密：语义相似度匹配，召回率72.3%
- BGE-M3稀疏：词级稀疏检索，增强词汇覆盖
- RRF融合：融合三路结果，召回率提升至86.1%
- BGE-Reranker：精排提升精确率

**性能指标**：
- 检索耗时：50-100ms
- Reranker耗时：30-50ms
- 端到端延迟：300-700ms

### 4.4 知识图谱增强检索

**技术说明**：通过实体关系抽取构建知识图谱，扩展RAG检索上下文。

**核心特点**：
- 10种实体类型：PERSON、ORGANIZATION、PROJECT、MEETING等
- 10种关系类型：参与、负责、汇报给、相关等
- 图谱扩展深度可配置（默认2层）
- 支持Cypher图查询（Neo4j模式）
- 内存+Neo4j双存储架构

### 4.5 全链路GPU加速

**技术说明**：关键AI组件均配置GPU加速，提升推理性能。

**已配置GPU加速的组件**：
- 复杂度分类器（Qwen3-0.6B）
- BGE-M3向量化模型
- BGE-Reranker重排序模型

**降级机制**：GPU不可用时自动降级为CPU，保障服务可用性。

### 4.7 企业级容错系统（重试+熔断+降级）

**技术说明**：基于微服务架构设计的完整容错体系，保障系统在异常情况下的可用性。

**核心组件**：

- **重试管理器（RetryManager）**：支持指数退避策略的异步重试机制
  - 可配置最大重试次数（默认3次）
  - 指数退避等待（1s → 2s → 4s...）
  - 支持指定重试异常类型白名单

- **熔断器（CircuitBreaker）**：基于状态机的熔断机制
  - 三种状态：CLOSED（正常）→ OPEN（熔断）→ HALF_OPEN（半开）
  - 可配置失败阈值（默认5次）和成功阈值（默认3次）
  - 自动重置超时（默认60秒）

- **降级管理器（FallbackManager）**：灵活的降级策略
  - RETURN_DEFAULT：返回默认值
  - RETURN_CACHE：返回缓存值
  - CALL_ALTERNATE：调用备用函数
  - THROW_EXCEPTION：抛出异常

**应用场景**：
- LLM服务调用失败时自动重试
- Redis/数据库断连时触发熔断，避免级联故障
- 向量化服务不可用时降级为词频向量化

### 4.8 人机协作确认机制（HITL）

**技术说明**：在关键决策节点请求人工确认，确保高风险操作的安全性和准确性。

**核心功能**：

- **确认类型**：计划审批、任务执行、工具调用、结果审核、关键操作
- **异步等待**：基于asyncio Future实现非阻塞等待用户确认
- **超时机制**：默认5分钟超时，自动处理超时场景
- **状态快照**：保存确认点的执行状态，支持确认后的状态恢复

**工作流程**：
```
Agent执行 → 检测高风险操作 → 发送确认请求 → 等待用户响应 → 继续执行/中止
```

### 4.9 Prompt模板市场与领域配置化

**技术说明**：完整的Prompt模板管理系统，支持会议场景的领域配置化。

**核心功能**：

- **模板分类**：会议总结、待办事项、决策记录、争议分析、问答分析、会议规划、跟进提醒
- **模板管理**：创建、更新、删除、搜索、渲染
- **领域配置**：会议时长、参与人数、时区、工作日、摘要长度等场景参数
- **变量支持**：模板支持动态变量替换

**内置模板**：7个系统模板覆盖会议全流程场景，支持用户自定义扩展

### 4.10 用户反馈闭环与Bad Case管理

**技术说明**：完整的用户反馈收集和迭代改进体系，支撑模型持续优化。

**核心功能**：

- **反馈收集**：支持评分（1-5星）、文字评论、指标记录
- **Bad Case自动标记**：评分≤2分或失败类型自动归档为Bad Case
- **分类机制**：事实错误、回答不完整等自动分类
- **根因分析**：结合反思系统生成分析报告和改进计划
- **性能报告**：反馈总数、平均评分、成功率、Bad Case分布统计

**迭代闭环**：
```
用户反馈 → Bad Case自动创建 → 根因分析 → 改进计划 → 实施改进 → 验证效果
```

### 4.11 Redis缓存体系

**技术说明**：多级缓存架构，提升系统性能和响应速度。

**缓存层级**：

- **向量检索缓存**：缓存向量检索结果
- **LLM响应缓存**：缓存LLM生成结果，避免重复调用
- **API缓存**：缓存高频API响应
- **分布式锁**：支持Redis分布式锁，防止并发冲突
- **限流**：基于Redis的接口限流

**缓存策略**：
- TTL自动过期
- 内存缓存降级（Redis不可用时）
- 缓存命中率统计

### 4.12 Prometheus可观测性体系

**技术说明**：完整的业务级监控指标体系，支持精细化性能分析和告警。

**自定义业务指标**：

- **RAG请求计数器**：按复杂度分级（S/R/C/A）统计请求量
- **RAG延迟直方图**：端到端延迟分布，8个桶区间（0.1s~10s）
- **Agent工具调用计数器**：按工具名称统计调用次数
- **检索召回率Gauge**：实时更新最新评估值
- **LLM错误计数器**：按错误类型分类统计

**集成方式**：
- `prometheus-fastapi-instrumentator`自动采集HTTP指标
- `/metrics`端点暴露所有指标
- 支持Prometheus自动发现和告警规则配置

### 4.13 RAG在线监控与告警系统

**技术说明**：基于RAGAS评估的实时监控体系，保障系统质量。

**核心功能**：

- **实时指标记录**：请求成功率、平均延迟、RAGAS六维指标
- **告警阈值检查**：
  - 错误率 > 10%
  - 平均延迟 > 5000ms
  - Faithfulness < 0.5
  - Answer Relevancy < 0.5
- **健康状态评估**：healthy/degraded两级状态
- **回调机制**：支持注册自定义告警回调函数

### 4.14 安全与合规体系

**技术说明**：企业级安全架构，涵盖认证、授权、数据脱敏和审计。

**核心组件**：

- **JWT认证**：HS256算法，60分钟过期，OAuth2密码流
- **RBAC权限控制**：四级权限（NONE/READ/WRITE/ADMIN），支持通配符权限
- **数据脱敏模块**：自动脱敏手机号、邮箱、身份证、银行卡、IP地址等敏感信息
- **审计日志记录器**：记录所有关键操作（CRUD、登录、权限变更），支持多维度查询

**应用场景**：
- 用户认证和接口权限校验
- 日志输出脱敏，防止敏感信息泄露
- 安全审计和合规检查

### 4.15 分布式锁与限流

**技术说明**：基于Redis的分布式协调机制，保障多实例部署下的系统稳定性。

**分布式锁**：
- 支持锁的获取和释放
- 原子操作，防止死锁

**限流机制**：
- 滑动窗口计数器算法
- 支持按IP/用户/接口多维度限流
- 429状态码响应，包含Retry-After信息

### 4.16 SSE流式输出

**技术说明**：基于Server-Sent Events的实时输出机制，提升用户体验。

**核心特点**：

- **实时思考过程展示**：Agent推理过程逐步输出
- **低延迟响应**：首字节快速返回
- **无缓冲传输**：设置`X-Accel-Buffering: no`确保实时性
- **客户端兼容性**：标准SSE协议，浏览器原生支持

**应用场景**：
- Agent对话界面实时展示思考链
- 长文本生成逐步输出
- 异步任务进度实时更新

### 4.17 Dynamic Tool Selection（动态工具选择）

**技术说明**：基于多策略的动态工具发现和选择系统，实现工具的自动注册和智能组合。

**核心特点**：

- **多策略发现**：支持四种策略（keyword_match、semantic_similarity、condition_evaluation、hybrid）
- **自动注册**：从配置、环境变量、目录自动发现MCP服务器并注册工具
- **规则引擎**：ToolCombinationEngine支持工具组合规划和条件触发
- **动态组合**：根据任务需求自动选择和组合多个工具

**工具选择流程**：
```
用户问题 → 意图识别 → 策略匹配 → 工具发现 → 条件评估 → 工具选择 → 执行
```

### 4.18 Reflection升级（反思系统）

**技术说明**：完整的Agent反思循环系统，支持重新规划、工具重新选择和答案重新生成。

**核心特点**：

- **反思循环**：`reflect_and_replan()`完整反思流程，置信度阈值自动停止
- **重新规划**：`_generate_new_plan()`方法支持反思后重新制定执行计划
- **工具重选**：`_select_new_tools()`方法支持根据反思结果重新选择工具
- **答案重生成**：`_regenerate_answer()`方法支持答案重新生成
- **置信度评估**：实时评估答案置信度，达到阈值自动终止迭代

**反思流程**：
```
执行 → 反思检查 → 置信度评估 → [低于阈值] → 重新规划 → 工具重选 → 重新执行 → ... → [达到阈值] → 输出答案
```

### 4.19 AI成本管理

**技术说明**：基于模型路由和Token预算的AI成本控制系统，实现成本优化和预算管理。

**核心特点**：

- **模型路由**：根据任务类型和复杂度选择模型（Simple→Qwen-turbo、Medium→Qwen-plus、Complex→Qwen-max）
- **Token预算**：支持每日/每月Token消耗限制，超预算自动降级
- **成本监控**：实时记录每请求Token消耗和费用估算
- **缓存策略**：相同问题直接返回缓存，避免重复调用
- **预算告警**：超过阈值自动告警

**成本优化效果**：
- 平均每请求成本：$0.0006
- 通过模型路由降低成本约60%
- 缓存命中率：约85%
