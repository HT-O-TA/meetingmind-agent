## 我的判断：现在应该先停一下扩层

你的两个判断都重要，而且优先级高于继续翻新工具调用层、输出层和反思层：

1. 文档口径不一致，会让后续开发、测试和面试表达都失去基准。
2. 没有真实效果证据和可重复演示，代码再完整也无法证明项目真正有用。

所以接下来建议按这个顺序走：

```text
文档收口 → 冻结当前版本口径 → 选定真实/脱敏样本 → 固定演示脚本 → 采集指标 → 根据证据决定下一层是否继续优化
```

## 第一优先：文档治理

### 目标

把文档分成三类，避免“历史设计被误当成当前实现”：

1. **当前口径**：项目总览、当前状态、输入层、规划层、记忆层、证据与限制。
2. **接口和运行**：API、启动方式、测试命令、环境变量。
3. **历史记录**：优化路径和第一/第二版架构，只用于追溯，不作为待办清单。

### 整理规则

- 每项能力只保留一个当前说明，其他文档只链接过去，不重复复制整段内容。
- 每个当前层文档都明确写“已实现、已测试、未验证、明确不做”。
- 所有数字必须注明来源：契约测试、合成数据、公开样例、真实数据或人工演示。
- 发现冲突时，以代码和最近一次可复现实验证据为准；没有证据就标为“未验证”，不能写成“已完成”。
- HTML、旧 DOCX 和历史 Markdown 不再继续扩写；需要保留时标成历史参考。

本轮已完成第一版收口：新增这份当前状态文档、文档治理清单、统一离线评测数据卡和固定五分钟演示说明。历史阶段文档仍保留，但不再作为当前完成度依据。

## 第二优先：真实效果证据

当前已落地一套 8 条项目自编脱敏会议评测集和报告：
`backend/evaluation/datasets/meetingmind_deidentified_v1.jsonl`、
`backend/evaluation/reports/meetingmind_deidentified_v1.md`。它能给出 Recall@K、MRR、引用正确率和待办 F1 的可复现数字，但样本还小，不能代表真实会议泛化。

本轮又审查了本地 AliMeeting Eval 和 VCSUM，生成 8 个会议源记录、26 场 VCSUM 测试会议的 158 条问题/答案候选，并完成 580 个审核单元的独立 AI 第一轮复核。当前状态是 `ai_reviewed_silver`：引用已按上游结构补全，待办与约束做了保守筛选。现在先审核 100 条分层 gold-pilot，尚未形成 gold 真值。

端到端 P50/P95、失败率、Token 和单请求成本使用 `scripts/measure_agent_runtime.py` 采集。当前没有启动真实 API 和供应商账单，所以这些线上数字仍为空，待接入服务后再生成报告。

### 先固定三条最小证据链

1. **会议问答链**：真实或脱敏会议文档 → 检索 → 带引用回答。
2. **会议行动链**：会议内容 → 待办/决策抽取 → 结构化结果 → 人工复核。
3. **受控工具链**：用户请求 → 规划 → 风险判断 → HITL → Jira 测试项目写入 → 回查 → 审计记录。

如果真实 Jira 凭据暂时不可用，第三条先做“工具拒绝/等待确认/幂等恢复”的可重复演示，但必须明确标注没有真实外部写入。

### 每条证据至少记录

- 输入样本编号、是否真实/脱敏/合成；
- 代码版本和配置；
- 任务完成率、结构化字段正确率；
- RAG 召回和引用覆盖情况；
- 约束保留率（尤其是“不要、除非、预算上限”）；
- 首 Token、总延迟、输入/输出 Token 和失败次数；
- 工具调用是否重复、是否正确阻止越权；
- 人工复核结论和失败原因。

## 第三优先：固定演示方式

固定入口已提供：`python scripts/demo_five_minute.py`。它覆盖 HTTP 正常/权限拒绝、工具确认门禁和队列恢复，并在 `artifacts/five-minute-demo/` 留下 manifest 与原始日志。工具确认演示不会执行真实 Jira 写入。

演示不应是临时输入一句话看结果，而应是可重复脚本：

1. 展示输入文件、用户身份和任务目标。
2. 展示输入层如何生成 `InputEnvelope/TaskAnchor`。
3. 展示检索引用、计划步骤和工具风险判断。
4. 展示正常结果、错误结果和被拦截结果各一个。
5. 展示任务 ID、审计 ID、Checkpoint 或 outbox 状态。
6. 最后展示指标和已知限制。

演示的重点不是“模型说得像不像人”，而是“输入、计划、工具、记忆、输出都有证据，失败时也能解释”。

## 现在暂缓什么

- 暂缓继续堆复杂工具、输出格式和反思策略。
- 暂缓恢复多智能体、多模态、复杂长期记忆和语义缓存。
- 暂缓用更大的模型或更大的上下文窗口掩盖真实效果缺失。

只有真实证据暴露出明确问题后，才继续翻新工具调用层、反思层或输出层，并且每次改动都要有前后对照。

## 当前最重要的结论

输入层、规划层、记忆层已经有一部分可运行的工程基础，但不能说“整体没有问题”。目前最大的风险不是再缺几个类，而是：文档口径没有完全冻结，真实会议效果、真实工具演示和生产环境恢复仍缺证据。

文档和最小证据/演示入口已经完成第一版；下一步是接入真实或公开长会议、启动隔离服务采集线上指标，再根据结果决定剩余三层的优化顺序。
