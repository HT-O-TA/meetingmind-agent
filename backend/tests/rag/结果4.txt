## 三、结果分析

### 核心问题：耗时仍需优化
评估平均 4.77s/题，未能达到 1s 以内的目标，根本原因：
- 每个问题需要 **13 次串行 embedding 调用**
  - 1次：对用户 query 做向量化（检索阶段）
  - 2次：计算 answer 与 expected_answer 的相似度
  - 10次：对 top_k=5 个 context chunk，每个单独计算与 answer 的相似度
- 加上 LLM（qwen-max）每次调用约 2-3s，总计 4-5s/题

## 四、下一步优化建议

| 优先级 | 优化方向 | 预期效果 |
|--------|----------|----------|
| P1 🔥 | 分层 Chunking（按说话人发言切分） | 上下文相关性和答案相似度显著提升 |
| P2 | 混合检索（BM25 + 向量） | 提升专有名词类问题的召回率 |
| P3 | 查询改写 / HyDE | MRR 提升 |
| P4 | 重排序（Reranker） | MRR 提升 10-20% |
| P5 | 上下文压缩 | LLM 回答更精准，token 消耗降低 |
| P6 | 评估加速 | 批量 embedding + 结果缓存，加快调试迭代 |

---
要突破 1s/题，有两个方向：
1. 跳过 LLM 生成，只跑检索指标 → 直接砍掉 2-3s
2. 批量 embedding：把 13 次独立 encode 合并成 1-2 次 encode_batch() 调用 → 节省约 0.5-1s
