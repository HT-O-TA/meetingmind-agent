# scripts 目录运行示例（大白话）

这份文档只说明 `scripts/` 下六个脚本怎么运行、运行前需要什么，以及输出结果在哪里。

## 0. 统一准备

在 PowerShell 中进入项目根目录，并激活 GPU Conda 环境：

```powershell
cd F:\project\meetingmind-agent
conda activate meetingmind-gpu
```

本地后端运行通常还需要：

- PostgreSQL 已启动，并且 `DATABASE_URL` 指向 `meetingmind` 数据库；
- Docker 中的 Redis、RabbitMQ、Milvus 已启动；
- 后端使用 `backend/.env`；根目录 `.env` 只给 Compose 使用；
- 模型已经放在根目录 `model/` 下。

如果命令需要数据库连接，建议先加载本地配置，或直接设置：

```powershell
$env:DATABASE_URL="postgresql+asyncpg://postgres:123@127.0.0.1:5432/meetingmind"
```

## 1. 数据库迁移：`apply_user_permissions_migration.py`

用途：给现有数据库补充权限、ASR、软删除和索引字段。升级数据库结构时运行一次即可，不需要每次启动服务都运行。

```powershell
python scripts/apply_user_permissions_migration.py
```

成功时没有复杂的业务输出；如果失败，优先检查 `DATABASE_URL`、数据库服务和数据库权限。

## 2. 部署预检：`preflight_deploy.py`

开发环境检查 Compose 配置：

```powershell
python scripts/preflight_deploy.py --mode development
```

生产环境检查必填变量和默认密钥：

```powershell
python scripts/preflight_deploy.py `
  --mode production `
  --env-file .env `
  --output artifacts/preflight-production.json
```

这个脚本只检查，不负责启动服务。Docker 没有启动时，Compose 运行检查可能失败，但这不等于代码本身有错误。

## 3. HTTP 业务主链：`demo_http_business_flow.py`

用途：通过真实 HTTP API 验证注册、登录、会议/文档操作和权限拒绝。

先启动后端 API，再运行：

```powershell
python scripts/demo_http_business_flow.py `
  --base-url http://127.0.0.1:8000 `
  --timeout 60 `
  --output artifacts/five-minute-demo/01_http_business_flow.json
```

输出文件会记录状态码和权限结果。比如私有文档返回 `403`、跨部门会议返回 `403`，代表权限门禁按预期生效，不是演示失败。

## 4. 五分钟固定演示：`demo_five_minute.py`

用途：一次性编排 HTTP 主链、工具确认和队列恢复三个演示步骤，并生成统一 Manifest。

```powershell
python scripts/demo_five_minute.py `
  --base-url http://127.0.0.1:8000 `
  --http-timeout 90 `
  --step-timeout 90 `
  --output-dir artifacts/five-minute-demo
```

重点查看：

```text
artifacts/five-minute-demo/manifest.json
artifacts/five-minute-demo/01_http_business_flow.json
artifacts/five-minute-demo/02_tool_confirmation.json
artifacts/five-minute-demo/03_queue_recovery.json
```

只有 `manifest.json` 中的 `status` 为 `passed`，才能称为三段演示完整跑通。

## 5. 固定实验集合：`run_fixed_demos.py`

用途：运行更完整的固定实验集合，包括 HTTP、队列、ASR 和 LoRA。它适合复现阶段性实验，不是日常启动后端的命令。

运行全部步骤：

```powershell
python scripts/run_fixed_demos.py `
  --output-dir artifacts/fixed-demos
```

只运行某一类步骤：

```powershell
python scripts/run_fixed_demos.py --demo http --output-dir artifacts/fixed-demos
python scripts/run_fixed_demos.py --demo queue --output-dir artifacts/fixed-demos
python scripts/run_fixed_demos.py --demo asr --output-dir artifacts/fixed-demos
python scripts/run_fixed_demos.py --demo lora --output-dir artifacts/fixed-demos
```

注意：ASR 需要本地音频和 ASR 依赖，LoRA 需要本地基座模型和适配器；缺少这些资源时，相应步骤会失败，但不影响 HTTP 主链代码本身。

## 6. Agent 性能测量：`measure_agent_runtime.py`

用途：对真实 API 发送评测问题，统计 P50/P95 延迟、失败率、Token 账本和可计算的单请求成本。

```powershell
python scripts/measure_agent_runtime.py `
  --base-url http://127.0.0.1:8000 `
  --dataset backend/evaluation/datasets/meetingmind_deidentified_v1.jsonl `
  --repeat 1 `
  --output artifacts/runtime-benchmark.json
```

只测指定会议或文档时：

```powershell
python scripts/measure_agent_runtime.py `
  --base-url http://127.0.0.1:8000 `
  --dataset backend/evaluation/datasets/meetingmind_deidentified_v1.jsonl `
  --meeting-id 1 `
  --document-id 1 `
  --output artifacts/runtime-single.json
```

如果没有真实供应商用量或价格参数，成本字段会保持为空，这是有意设计的，不会把预算上限伪装成实际成本。需要估算成本时再传入：

```powershell
python scripts/measure_agent_runtime.py `
  --dataset backend/evaluation/datasets/meetingmind_deidentified_v1.jsonl `
  --output artifacts/runtime-cost.json `
  --input-price-per-1k 0.01 `
  --output-price-per-1k 0.02
```

## 推荐复现顺序

```text
1. preflight_deploy.py       检查环境
2. apply_user_permissions... 数据库升级（首次或升级时）
3. demo_http_business_flow.py 验证主业务链
4. measure_agent_runtime.py  测量真实 API 性能
5. demo_five_minute.py       生成面试演示证据
6. run_fixed_demos.py        复现 ASR/LoRA 等扩展实验
```

其中最重要的是 HTTP 主链、性能测量和五分钟演示；数据库迁移、部署预检和固定实验集合属于工程复现辅助。
